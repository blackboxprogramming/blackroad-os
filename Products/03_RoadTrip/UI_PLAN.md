# UI Plan — RoadTrip

## First-run experience
User creates or opens a mission room. They see a clean workspace with agent/model roster, task board, message timeline, and easy ways to add context or request handoffs.

## Main screens
1. Mission Dashboard – Title, agents, tasks, quick actions.
2. Agent Threads – Parallel conversations with different models/agents.
3. Context Panel – Attached files, previous work, memory.
4. Handoff Packet Viewer – Structured output ready to send to other products.
5. Summary & Receipts – Auto-generated notes and proof links.

## Empty states
- New room: Helpful prompts for first task or agent selection.
- No agents selected: Suggestions based on task type.

## Primary flows
1. Start mission → Add task/context → Choose agents
2. Work with agents → Review visible reasoning
3. Generate handoff → Send to RoadCode / RoadWork / RoadBook etc.
4. Review summary → Save to RoadWire

## Navigation
- Top bar: Mission title + status
- Left: Agent roster + tools
- Center: Main work area (threads/tasks)
- Right: Context and memory

## Agent presence
Agents should be clearly visible with roles, current activity, and easy switching.

## Receipts/proof display
Handoffs, important decisions, and summaries should generate clear RoadChain receipts.

## Mobile considerations
Thread-based work should work well on mobile. Complex multi-agent coordination may be richer on larger screens.

## Black-and-white baseline
All core flows must be clear without color or heavy visuals.
